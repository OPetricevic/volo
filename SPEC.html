Overview

What is Volo?

The Problem

Browser interaction is still keyboard-and-mouse driven. You type URLs, click bookmarks, type search queries. Repetitive actions stay repetitive — there's no learning, no adaptation.

The Solution

Volo is a voice-activated assistant that lives in your browser (and on your desktop). It listens for commands, executes them instantly, and learns your patterns to get faster over time.

UX

Microphone Permission Flow

🎤

Volo needs microphone access

To listen for voice commands, Volo needs permission to use your microphone.

You can change this anytime in Volo settings.

Always

Continuously listens for "Hey Volo" in the background. Restarts on silence timeout. Best experience.

Once (Push-to-talk)

User clicks the Volo icon or presses a hotkey to activate. Mic only active during command.

Off

No mic access. Extension is passive. Can still use text input for commands.

Intelligence

Pattern Learning (AI Layer)

A lightweight model that improves over time — not a neural network, but a smart frequency system with recency weighting.

📊 Frequency Tracking

Tracks most searched terms and most visited sites. Higher frequency = higher ranking in suggestions.

🕐 Time-of-Day Patterns

"In the morning, user usually opens Gmail." Learns temporal habits and pre-ranks accordingly.

💡 Autocomplete

After "Hey Volo", suggests likely commands based on history and current context (time, active tab).

🔍 Fuzzy Matching

If user says "open tube" → likely means YouTube. Learns abbreviations and nicknames over time.

How It Works Internally

// Simplified pattern scoring
score = frequency × recency_weight × time_bonus

// recency_weight: exponential decay (recent = higher)
// time_bonus: if pattern matches current hour bracket
// frequency: raw count of times this pattern was used

// Example: user searches "react docs" 15 times, mostly at 9am
// At 9:05am, "react docs" gets boosted to top suggestion

API Design

Endpoints

POST /api/v1/command Process a voice command
GET /api/v1/suggestions Autocomplete based on history
GET /api/v1/history Recent command history
DEL /api/v1/history Clear history
POST /api/v1/auth/register Register device
POST /api/v1/auth/token Get auth token
GET /api/v1/settings User settings (synced)
PUT /api/v1/settings Update settings

Request Example

POST /api/v1/command
{
  "transcript": "open youtube play lofi hip hop",
  "context": {
    "current_url": "https://google.com",
    "timestamp": "2026-06-01T08:35:00Z"
  }
}

Response Example

{
  "action": "open-and-play",
  "target": "youtube.com",
  "query": "lofi hip hop",
  "confidence": 0.95,
  "suggestions": [
    "lofi hip hop radio",
    "lofi hip hop beats"
  ],
  "execute": {
    "url": "https://youtube.com/results?search_query=lofi+hip+hop",
    "auto_play": true
  }
}
Data

Database Schema

-- Users / devices
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ DEFAULT now(),
  device_name TEXT,
  settings JSONB DEFAULT '{}'
);

-- Command history
CREATE TABLE commands (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  transcript TEXT NOT NULL,
  parsed_action TEXT NOT NULL,
  parsed_target TEXT,
  parsed_query TEXT,
  confidence REAL,
  executed_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_commands_user_time
  ON commands(user_id, executed_at DESC);

-- Pattern learning (frequency model)
CREATE TABLE patterns (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  pattern_type TEXT NOT NULL,   -- 'search', 'site', 'command'
  value TEXT NOT NULL,
  frequency INTEGER DEFAULT 1,
  last_used TIMESTAMPTZ DEFAULT now(),
  hour_weights JSONB DEFAULT '{}', -- {"8":5,"9":3}
  UNIQUE(user_id, pattern_type, value)
);

CREATE INDEX idx_patterns_user_freq
  ON patterns(user_id, frequency DESC);

Roadmap

Implementation Phases

Phase 1 — Core Voice Loop

Extension
  1. Scaffold extension with Vite + React + Manifest V3
  2. Implement Web Speech API listener in content script
  3. Wake word detection ("Hey Volo")
  4. Basic command parsing (client-side, no backend)
  5. Execute: search Google, open URL
  6. Popup UI: status indicator, mic toggle

Phase 2 — Go Backend

API
  1. Scaffold Go API with Chi router
  2. Implement /api/v1/command with rule-based intent parser
  3. Database setup (SQLite for dev)
  4. Command history storage
  5. Connect extension to backend

Phase 3 — Pattern Learning

AI
  1. Implement frequency model in Go
  2. Suggestions endpoint based on history
  3. Time-of-day weighting
  4. Fuzzy matching for site names

Phase 4 — Desktop App

Electron
  1. Scaffold Electron app with React renderer
  2. System tray + global hotkey
  3. Embedded BrowserView for web navigation
  4. Share voice logic with extension
  5. Desktop app launching (shell exec)

Phase 5 — Landing Page

Web
  1. Scaffold React + Vite site
  2. Hero with demo/video placeholder
  3. Features breakdown
  4. Download links
  5. Deploy to static hosting

Phase 6 — Polish

Final
  1. Visual feedback (listening animation, confirmations)
  2. Error handling and retry logic
  3. Settings sync across devices
  4. Onboarding flow (mic permission, tutorial)
  5. Cross-browser testing (Chrome, Opera, Edge)
Academic

Thesis Angles

This project supports several research directions for a bachelor thesis.

🗣 Voice-Driven HCI

How voice interfaces change browser interaction patterns and reduce friction in repetitive tasks.

🧠 Personalized Search

Lightweight ML for user behavior prediction. Frequency models, recency decay, temporal patterns.

🏗 Cross-Platform Architecture

Shared logic across browser extension + desktop app. Code reuse strategies and platform abstraction.

💬 Intent Parsing

NLP-lite approach to command understanding. Rule-based vs ML-based intent classification.

⚡ Edge vs Server

Client-side wake word detection vs server-side processing. Latency, privacy, and accuracy tradeoffs.

🔒 Privacy by Design

Always-listening microphone with user control. Local-first processing, opt-in data sharing.
